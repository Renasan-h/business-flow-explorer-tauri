# P0 Windows実機受入検証

この手順はCIでは代替できないWindows 11実機での検証を記録するためのものです。**未実施を合格扱いにしない**こと。各ケースに実行日時・Windowsバージョン・アプリのコミットSHA・期待結果・実結果・スクリーンショットまたはログ・合否を記録する。

## 事前準備

- develop_tauri の対象SHAを記録し、同一SHAで生成されたNSISとPortable ZIPを用意する。
- テスト専用のYAMLフォルダを作り、編集前のファイルを別フォルダへバックアップする。
- 同じテスト用シナリオをWeb版とTauri版で開ける状態にする。
- 結果は「合格 / 不合格 / 未実施 / 対象外」のいずれかとし、対象外には理由を付ける。

## A. Windowsデスクトップ配布物

| ID | 手順 | 期待結果 |
|---|---|---|
| WIN-01 | NSISインストーラーを実行し起動する | インストール・初回起動・アイコン表示に問題がない |
| WIN-02 | アプリを閉じ再起動する | クラッシュせず画面が復元・再描画される |
| WIN-03 | Portable ZIPを別の空フォルダに展開して起動する | インストールなしで起動できる |
| WIN-04 | Portable実行ファイルを閉じ、別フォルダに移動して再起動する | 起動できる。設定・データの保存場所は観測して記録する |
| WIN-05 | 画面サイズを変更し、最大化・復元する | キャンバス、サイドバー、ダイアログが操作できる |
| WIN-06 | 日本語・空白を含むフォルダからYAMLを開く | 文字化け・パスの誤解釈がない |

## B. 保存・未保存変更・競合

| ID | 手順 | 期待結果 |
|---|---|---|
| DATA-01 | 新規フローを作りノードと通信線を追加して保存する | 新規YAMLが作成され、再読込後も内容が一致する |
| DATA-02 | 既存YAMLを編集して上書き保存し、再起動して開く | ノード・通信・IF定義が維持される |
| DATA-03 | 編集後「再生画面へ戻る」を押し「編集を続ける」を選ぶ | 編集内容が残る |
| DATA-04 | 編集後「保存せず戻る」を選ぶ | 元ファイルは変更されない |
| DATA-05 | 編集中に外部エディターで同じYAMLを書き換えて保存を試す | 競合エラーとなり、外部変更を上書きしない |
| DATA-06 | DATA-05の競合後「保存して戻る」を選ぶ | 編集画面に残り、未保存内容が保持される |
| DATA-07 | 読み取り専用ファイル・書き込み権限のないフォルダで保存する | 保存失敗が表示され、既存データは保護される |
| DATA-08 | 保存先のファイルを外部から削除・移動して保存する | エラーを表示し、無言で別ファイルを生成しない |
| DATA-09 | 保存中にアプリを強制終了した場合の復旧可否を調べる | 元ファイルと一時ファイルの状態を記録する。復旧保証は実装と実測に基づき判定する |

## C. Web版との機能互換性

各ケースを**同じYAML**でWeb版とTauri版それぞれ実行し、スクリーンショットと生成YAMLの差分を残す。

| ID | 比較する操作 | 期待結果 |
|---|---|---|
| PARITY-01 | シナリオ一覧、カテゴリ切替、YAML読込 | 表示内容と読込結果が一致する |
| PARITY-02 | ノード追加・移動・サイズ変更・削除・複製 | 同じ編集結果になる |
| PARITY-03 | 接続線の追加・往路/復路・折れ線編集 | 通信方向と描画結果が一致する |
| PARITY-04 | 領域追加・編集・削除、複数選択・移動 | 同じ操作が可能 |
| PARITY-05 | ズーム、表示リセット、負座標への移動 | ノード位置・表示範囲が正常 |
| PARITY-06 | Undo/Redo（ノード・線・領域・プロパティ） | 同じ履歴操作が可能 |
| PARITY-07 | 再生・停止・速度切替・分岐選択 | 同じステップ順と表示になる |
| PARITY-08 | 双方向通信、サブシナリオ、IF仕様参照 | 接続・情報表示・再生結果が一致する |
| PARITY-09 | YAML保存・再読込 | 意図しない情報欠落がない |
| PARITY-10 | 不正YAML、欠落参照、保存失敗 | エラーを表示しデータを破壊しない |

## 完了判定

- すべての必須ケースが「合格」、または理由を明示した「対象外」である。
- 不合格ケースには再現手順・期待結果・実結果・原因・修正コミットを残し、修正後に再実行する。
- 対象コミットの GitHub Actions が完了し success である。
- **CI成功のみでWindows実機検証やWeb/Tauri互換性検証を完了とみなさない。**

# Windowsコード署名・配布方針

Windows向け配布物のコード署名と安全な配布に関する方針です。

## 未署名配布

未署名のNSISとPortable ZIPでは発行元の署名を確認できません。Windows Defender SmartScreenやブラウザの警告が出る可能性がある。警告を無条件に無視するよう利用者へ促さない。

## 比較

| 選択肢 | 利点 | 留意点 |
| --- | --- | --- |
| 未署名で配布 | 証明書・秘密鍵の管理が不要 | 発行元の信頼を示せず警告が出る可能性 |
| 商用コード署名証明書（OV等） | 発行元情報を署名に含められる | 費用・本人確認・有効期限管理・秘密鍵保護が必要 |
| EV等の厳格な証明書 | 厳格な本人確認・鍵保護要件 | 費用・手続き負担が大きい。SmartScreen警告の完全な回避は保証されない |
| クラウド署名サービス | 秘密鍵をCIへ直接配置せずに運用できる構成がある | 対応サービス・費用・認証・CI権限の検討が必要 |

費用は契約先・法人/個人の資格・期間によって変動するため、実際の見積もりを取得してから確定する。

## 将来署名する場合の要件

1. 証明書を取得し、署名対象（インストーラー・Portable exe）と署名順序を確定する。
2. 秘密鍵はGitHubリポジトリ、ログ、Artifactへ格納しない。可能ならハードウェア保護または署名サービスを利用する。
3. 署名ジョブは手動ワークフロー・保護されたEnvironment・最小権限で実行する。
4. Windows SDKの `signtool verify /pa /v` 等で署名と証明書チェーンを検証する。
5. 署名後にハッシュと配布物を記録し、NSISとPortable ZIPの両方を実機で起動する。
6. 証明書の失効・漏えい・更新時の手順を準備する。

## 未署名で公開する場合の利用者向け説明

「この配布物は現在コード署名されていません。Windowsが発行元不明の警告を表示することがあります。GitHubの公式リリースページから取得し、ファイルの出所を確認してください。心当たりのないファイルや出所を確認できないファイルは実行しないでください。」

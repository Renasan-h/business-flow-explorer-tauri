# P0 Windowsリリース候補・実機受け入れ試験

対象：`develop_tauri` の特定コミットから生成したNSISインストーラーおよびPortable ZIP。**本書はテストケースと記録様式であり、実行済みの証拠ではありません。**

## 事前条件

- Windows 11 x64、WebView2、ローカルの書込可能なシナリオフォルダ、別途読み取り専用フォルダを準備。
- GitHub Actionsが利用できる場合、`Full development checks` を対象コミットで手動実行し、Artifact `business-flow-explorer-dev-windows` を取得。CIが起動できなければ同じコミットをWindows環境で `npm ci`、`npm run build` して生成。
- インストーラーとZIPは同一SHAから生成する。Portable ZIPを任意のユーザーディレクトリへ展開する。
- 元データのバックアップを取り、検証専用のYAMLを使用。競合試験で既存の実データを破壊しない。
- 実行環境・日時・コミットSHA・配布ファイル名・ビルド方法を記録する。

## 自動検証と実機検証の区別

- `npm run build:web`：TypeScriptとWebビルド。
- `node scripts/test-editor-e2e.mjs`：PlaywrightによるブラウザE2E。ネイティブのWindowsダイアログ・ファイル権限・exe起動は代替できない。
- `cargo test --manifest-path src-tauri/Cargo.toml`：Rustのネイティブ処理テスト。
- `cargo check --manifest-path src-tauri/Cargo.toml`：Rustコンパイルチェック。
- `npm run build`：Tauri配布ビルド。**ビルド成功だけではWIN-01〜26の実機動作は保証されない。**

## リリース判定

- P0の重要ケースでFAILが残る場合は正式リリースしない。
- CIが請求制限等で開始できない場合は、実行成功と見なさずBLOCKEDを記録する。
- Windows実機の操作権限がない場合は、WIN-01〜26をNOT RUNと記録し、実行済みと報告しない。
